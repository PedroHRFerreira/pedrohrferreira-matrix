# Matrix Initialization Protocol — Approved Design

## Outcome

Replace the physical retro television with a full-viewport browser-as-terminal experience. Red and Blue realities remain unchanged and are still mounted exclusively after an in-memory choice.

## Sequence

1. `static-noise`: five seconds of restrained full-screen analog noise, with no copy or controls.
2. `terminal-connecting`: black terminal, blinking cursor, short suspense pause.
3. `initial-message`: localized connection and identification lines type character by character, identifying the user as `New`.
4. `waiting-first-enter`: explicit Enter instruction plus a touch-accessible continue control.
5. `reality-question`: the localized reality question types at a slower dramatic pace.
6. `waiting-second-enter`: a second explicit confirmation is required.
7. `pill-selection`: minimal pill controls appear as part of the terminal; keyboard focus or pointer selection is required before confirmation.
8. `transitioning-red|blue`: the existing reality-specific transition finishes before the selected tree mounts.

Repeated or premature Enter events are rejected by the explicit state machine.

## Motion and accessibility

- Standard mode uses low-contrast animated grain, subtle horizontal interference, variable per-character timing, and a blinking cursor.
- Reduced-motion mode preserves the complete narrative duration and immersion with static/attenuated noise, slower fades, and complete lines appearing after a comfortable pause instead of prolonged character animation.
- No physical monitor, television frame, expanding screen, autoplay audio, form field, or persistent reality preference.
- All controls have accessible names, visible focus, touch targets, and color-independent labels.
